# DFCH 遠征模擬器

以遊戲遠征系統為研究基礎的網頁模擬器專案。

目前目標不是模擬戰鬥數值，而是完整保留會影響遠征抽選的流程，最後只統計：

- 鑽石（含普通掉落、Dia Fever、5000 / 7777 / 9999）
- 羈絆道具（28 種 rewardId）
- 後續的效率比較（依英靈步行速度）

## 開發階段

### V1 — UI（目前）

- 地圖選擇
- 1 名隊長 + 最多 11 名隊員
- 隊長統率力輸入與官方隊伍容量公式

- 官方隊伍步行倍率計算
- 收集家 I / II / III 選取
- 觀緣眼鏡「擁有 / 未擁有」開關
- 模擬次數設定
- 鑽石 / 羈絆統計版面
- 手機優先響應式 UI

目前不執行正式事件抽選。

### V2 — 英靈速度公式

第一階段公式已從 3.16.0 IL2CPP 確認並提前接入 V1：

- 隊長的步行等級權重 = 2
- 每名隊員的步行等級權重 = 1
- `Lavg = (2 × 隊長步行等級 + Σ隊員步行等級) / (2 + 隊員數)`
- `WalkSpeedMultiplier = 0.8 + (Lavg / 100) × 3.2`
- 隊伍總人數上限公式：`max(1, floor(統率力 / 20) + 1)`

例如統率力 230：

`floor(230 / 20) + 1 = 12`

即 1 名隊長 + 11 名隊員。

仍待確認：

- 面板顯示的 km/s 如何由角色內部步行等級換算
- 個別速度能力 / 狀態修正如何進入 `GetTotalLevel(2)`
- 是否存在額外地圖或事件速度修正

### V3 — 地圖邏輯

接入：

> 必勝 / 無敵

## 專案結構

```
index.html   V1 主介面
styles.css  響應式樣式
app.js      UI 狀態與互動
```

之後會逐步拆成：

```
data/
  dungeons.json
  events.json
  drops.json
  abilities.json
  artifacts.json

src/
  speed.js
  dungeon.js
  weights.js
  simulator.js
  statistics.js
```

資料層與公式層會分開，避免把官方數值直接寫死在 UI 裡。

## V1 注意

目前 V1 已經開始使用第一批已確認的官方公式：

- 隊伍容量：已套官方統率力公式
- 隊伍步行倍率：已套官方「隊長 ×2、隊員 ×1」加權公式
- 面板 km/s → 內部步行等級：尚未完成映射
- 地圖時間：尚未計算
- 羈絆加成：尚未套官方最終疊加公式
- 模擬按鈕：目前只驗證操作流程

因此目前若要看到官方隊伍步行倍率，必須手動填入每名英靈的內部「步行等級」。面板 km/s 目前只作為角色資料顯示，不會被錯誤地直接拿去平均。

詳細逆向紀錄見 `docs/speed-formula.md`。

後續每確認一條官方公式，就直接替換對應模組，不重做 UI。
