# V2.0.0：帳號配置與遠征介面

以 V1.6.0 為基底，保留鑽石抽取及輪盤。資料版本為官方 3.16.0。

## 帳號設定

六種神器在最上方集中設定，與收集家隊伍設定分離。神器數值按官方初始值、每級差值及最大等級計算；單級神器用勾選，多級神器用持有數量。

| 神器 rewardId | 能力 | 模擬效果 |
| --- | --- | --- |
| 301009049 | 10513 | 羈絆贈禮權重 +30%，與收集家相乘 |
| 301005025 | 10506 | 首領持續掉落率 +1 個百分點，最高 float32(0.99) |
| 301005015 | 10504 | 每級探索事件權重 +10%，最多三級；100% 時排除探索事件 |
| 301009040 | 10508 | 限定神器權重 ×1.5，再套探索解鎖的限定權重加成 |
| 301008114 | 10510 | 首領池加入群組 10000000 的 14 筆魂之果物／長壽幻酒 |
| 301005007 | 10502 | 原始寶石數量 +30%，再依參照地圖換算 |

首領最低抽選次數依加成後持續率計算；例如 0.75 加成為 float32(0.76) 後，最低次數由 4 變為 5。

寶石先套探索加成並取整，再套神器加成，最後進行地圖貨幣轉換與取整。預覽與實際抽選使用相同函式，顯示的是單次抽選條件機率，不是整場取得率。

官方表格中的 305000xxx 魂之果物與 305001xxx 羈絆贈禮分開統計；兩者都保留在全部獎勵清單。

## 探索與保存

- 全部地圖 100% 為覆蓋開關；取消後恢復各圖原有探索設定。
- 獨立模式不修改帳號設定。連續模式每輪結算後更新神器、解鎖旗標及各圖探索率；新效果自下一輪起生效。
- 連續模式的當日一般鑽石仍沿用各地圖紀錄，可在統計頁調整。
- 帳號設定使用 `dfch-account-settings-v2`；統計保留原本 `dfch-expedition-records-v1`。
- 初次進入新版且尚無帳號設定時，從舊版連續紀錄遷移神器最大已知持有量、旗標及各圖最新探索率。觀緣眼鏡沿用原介面的預設擁有。
- 帳號設定與統計分別匯入／匯出。重置統計不清除帳號設定。匯入舊統計不會覆蓋已建立的帳號設定。
- 讀取錯誤不覆寫原設定，並阻止模擬；可匯入有效帳號設定檔復原。儲存失敗會顯示錯誤並停止後續模擬。

## 資料來源與檢查

`data/artifacts.json` 保留六筆 ArtifactTable 原始欄位、首領額外群組及道具名稱；`artifact-data.js` 是相同資料的瀏覽器版本。

`ExpeditionBossDropAbilityBonusTable` 的 MonoBehaviour pathID 76116 指定能力 10510 對應群組 10000000。原始資料 SHA-256 與擷取筆數保存於 [證據檔](evidence/v2-artifact-source.json)。重建程式為 `scripts/build-artifacts.py`。觀緣眼鏡因官方繁中名稱欄位空白，沿用既有介面譯名。

本次也將函式 106 的百分比耐力傷害處理改為已核對的空操作；目前接入地圖沒有可到達的序列使用此函式。

驗證包含原有十三張地圖與所有核心回歸、新增神器與加成測試、實際 HTML 的跨圖設定／保存／重置隔離、鑽石抽取與輪盤操作。HTML 互動以 jsdom 驗證；此工作環境未進行真實瀏覽器截圖與視覺驗收。

## 尚未涵蓋

使用者指定的無敵必勝、0 秒戰鬥與免傷是模擬假設。無限耐力或自訂隊伍最終耐力保留，不依角色及神器重新估算耐力。活動倍率、其他角色專屬事件、經驗、年齡、寶箱開箱、真實遠征耗時及跨日重置未納入。面板速度反推亦有精度限制，因此不宣稱整場逐種子與原版完全一致。

既有統計不會重新計算；新版加成改變分布後，與舊統計混合的平均值不可直接當作新版單一配置的結果。
