# V1.2 第一張地圖可執行模擬

此版使用同一份官方 **3.16.0** 資料。工具版本由 V1.1 更新為 **V1.2**，不表示遊戲版本更新。`individual_(1).zip` 與先前壓縮檔解出的 individual_.bundle 相同：481711569 bytes，SHA256 `9dcaa549d68f4a14ad28a672ae348ea2d6ad905e7b76a501ffdf553ef8469217`。

## 已串接的七段

| 項目 | 本版行為 |
|---|---|
| 候選池 | 共用、基本戰鬥／掉落、探索解鎖、秘石、首領；礦脈以 MergeDungeon 加入基本池 |
| 能力與條件 | 現有 UI 的收集家 I／II／III 與觀緣眼鏡；探索完成、當日起始上限、秘石前置旗標及當輪解鎖排除 |
| 事件序列 | 按官方序列依序執行；支援目前配置所有可到達事件的 18 種函式 |
| 整輪生命週期 | 小數移動、終點攔截、首領一次性、整串事件後結束判定、礦脈 20 進度到期 |
| 獎勵 | 初抽、數量、演出、鑽石上限重抽、限定神器／持有上限、探索寶石加成、寶箱種類轉換、秘石與最終結算 |
| 亂數 | 整輪共用已核對的 System.Random；保留樣本、數量、演出、怪物與小數進度呼叫 |
| 結果與批次 | 總量、每輪平均、取得輪數比例、事件計數、首輪／末輪明細、亂數明細、可中止；獨立及連續模式 |

「18 種」不是全部 24 種角色事件函式。其他專屬能力尚缺生命、恢復與陷阱相關角色狀態；**不啟用這些能力，遇到未支援配置會在執行前拒絕，而非略過事件**。此版不主張所有角色能力或全部地圖完成。

## 核對與運算細節

- 動態生成：`0x34ba1cc`、基本掉落 `0x34ba720`、基本戰鬥 `0x34bb734`、首領 `0x34bbc74`、探索解鎖 `0x34bd8ec`、秘石 `0x34babb8`。生成順序及候選零權重保留。
- 秘石生成須持有前置旗標 6504；群組內第一個非空解鎖旗標是 6602，事件條件 FlagLocked 使用 6602。兩個 UI 選項分别代表可搜尋與已取得。
- 事件選擇 `0x2d06568`；forced 優先且不抽事件亂數；同權重保留第一列。探索 100% 排除增加探索率事件。當日起始一般鑽石已滿時排除第一張地圖的礦脈事件；有礦脈期間不重複啟動。
- 礦脈區域 9901 只加入自訂動態候選，不重複加入共用事件。終點／耐力結束判定在區域到期更新之前。
- `0x34b0b1c` 掉落、`0x34b0738` 上限重抽、`0x34b1950` 寶石數量、`0x34b1574` 限定權重。基本池上限重抽發生於初抽數量及演出已消耗之後；不能倒帶亂數。
- **名為 BigInteger 的包裝使用 CryptoDouble**：`0x340a544 → 0x340a39c → 0x2fd2d34`；乘法 `0x2fd1bac` 使用 double。不能因名稱而把 0.48 權重截成 0。float32 權重與進度仍依原路徑保留精度。
- 怪物配置 `0x34ac8b4` 使用 `Next(min,max)`，上限不包含；基本組 1–3 名。強制首領／探索怪物仍消耗 `Next(0,0)`。掉落數量則使用 `Next(min,max+1)`，上限包含。
- 掉落 max<1 時直接取 min；min=max 且 max>=1 仍呼叫亂數；只有一種演出也消耗 alias 抽選。整數移動進度仍抽一次。
- 首領先合併正值群組；續抽率 0.75，至少四次，無物品也算一次；每次取得神器後更新持有判斷。
- 探索新增候選以出發快照生成，當輪不新增；數量／限定權重加成使用當下探索率。下一輪才生成新門檻事件。
- 當日鑽石上限以出發快照判斷，可在一輪中超過 500；下一輪重新檢查。神級鑽石不受一般鑽石上限排除。

## 操作與統計口徑

1. 選第一張地圖，填未啟動加速技能的面板速度、收集家及持有狀態。
2. 選無限或自訂隊伍耐力、起始探索 0%／100%、次數及種子。
3. 每輪獨立固定所有起始條件；連續遠征承接探索、神器持有、秘石及當日鑽石。每輪耐力重置為玩家設定。
4. 首輪使用輸入種子；後續使用另一個相同種子建立的 System.Random.next() 種子序列。這是**批次策略**，尚未確認官方新遠征種子的寫入方式。
5. 中止僅保留已完成輪，未完成輪不結算。配置在開始時快照；執行中修改欄位不影響當批。

取得輪數比例是至少取得一次的完成輪數／完成輪數，並非原始事件权重。統計包含全部完成輪；為控制手機負載，只保留第一／最後輪明細，畫面最多列 1,000 筆日志與亂數。中止時最後完成輪若不是保留明細輪，仍有結算統計但日志為空。

## 驗證與限制

`node tests/simulator.test.cjs` 包含 1,800 輪起始探索門檻／速度組合、終點首領一次性、0.8 最低倍率、滿級神器、當日起始鑽石滿額、秘石、礦脈池及到期、耐力耗盡、固定種子重播、批次承接与取消。seed=42 fixture 是回歸測試，**不是原版整輪輸出的獨立 oracle**。亂數原語另有 APK 原指令 Unicorn 驗證的 896 個 double 與 35 個整數向量。

保留使用者指定的秒殺、戰鬥 0 秒、無限／自訂耐力。未重現原版戰鬥內部亂數，不宣稱相同種子即可重現原版含戰鬥整輪。面板三位小數反推速度仍是估計；未計算角色經驗分配、寶箱開箱、其他神器能力加成、跨日時間與官方新種子寫入。原地圖倒數 600 秒不除以移動倍率。

已有分支來源核對與整合測試，尚無官方完整遠征日志逐局比較，因此本版是明確限定配置的可運作模擬，不能標示為全部玩法與官方完全一致。

網頁整合驗證：`scripts/verify-simulator-ui.cjs` 使用 jsdom 直接載入 index.html 的所有腳本，驗證單輪、連續 100 輪、無效輸入保留結果、自訂耐力、百萬輪中止與探索 100%。另行安裝 jsdom 後可執行；也可用 DFCH_JSDOM_PATH 指向既有套件。此為 DOM 功能驗證，未完成真實手機瀏覽器的視覺檢查（本環境 Chromium 下載失敗）。

數值包裝原指令另保存於 [event-engine-numeric-arm64.txt](evidence/event-engine-numeric-arm64.txt)。

## V1.2.1 亂數操作修正

預設每次開始由瀏覽器 crypto.getRandomValues 產生新 int32 種子，再交給已核對的 System.Random；這是模擬器入口策略，不主張為官方種子生成方法。固定種子改為明確的重播選項；相同種子及配置重跑整批相同是預期行為。批次內原本就使用不同子種子，未重複同一輪。DOM 測試增加兩次新種子抽取驗證。
